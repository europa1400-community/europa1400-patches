# AGENTS.md: instructions for coding agents (Codex, Claude Code, Cursor, ...)

Public repository: patch loader and patches for Europa 1400 Gold. Read [docs/legal.md](docs/legal.md) and
[docs/architecture.md](docs/architecture.md) before changing anything. Language: code, comments and docs in English;
talk to the user in the user's language.

## Hard rules

1. **No code from the decompilation.** The private repository `europa1400-decompilation` (`DECOMP_DIR`) may be read to
   understand the game. Never copy, translate or paraphrase its C code, Ghidra output or disassembly into this
   repository. Write own code from behaviour descriptions and interface knowledge (names, addresses, offsets, message
   formats). If a function must be replaced as a whole, describe the behaviour first, then implement it anew.
2. **No game files, no recordings**: nothing from the game directory, no byte arrays taken from game files, no `*.e1rec`.
   Build tables contain names, RVAs and signatures only (generated by `tools/build_table.py`).
3. `uv run tools/check_repo.py` and `./scripts/build.ps1 -Test` must pass before a commit.
4. Never push, tag or publish a release without an explicit instruction. Commit only when asked or at the end of a
   requested work package; one topic per commit.
5. No subagents or parallel agents unless the user asks for them.

## Workflow

- Build/test: `./scripts/build.ps1 -Test` (MSVC x86 via vswhere). Never commit `build*/`, `dist/`, `.env`.
- New patch: `./scripts/new-patch.ps1 <id> -Name "<name>"`; fill `patch.ini` (`targets`, `[builds]`, `[symbols]`), add
  used symbols to `builds/symbols/<target>.txt`, refresh tables with `tools/build_table.py` (needs `DECOMP_DIR`).
- Behaviour must be proven: transparency of the loader with `./scripts/replay.ps1` (byte-identical to the original);
  fixes with dedicated tests (fault injection or new recordings), described in the patch's README/comments.
- Game test: `./scripts/install-dev.ps1` (non-destructive), log in `<game>/e1400patch/logs/e1400patch.log`.
- Patch API changes: append members to `E1400PatchApi`, bump `E1400_PATCH_API_VERSION`, keep old behaviour; describe it in
  the `feat:` commit (it becomes the release notes).
- Versions: the loader version comes from the release tag `v<x.y.z>` (git describe); `version=` per patch manifest.
  Commits and PR titles use Conventional Commits; releases: Actions → Release → Run workflow (docs/development.md).

## Facts that are easy to get wrong

- The game loads `server.dll` only when hosting; the path comes from `game.ini [Network] Server=`. Clients never load it.
- The game unloads the server with `FreeLibrary` (no `Exit` call); the shim detaches the loader and unloads the original
  then, so the next hosted game starts fresh.
- WS2_32 imports go by ordinal (`"#16"` = recv) in the original and in `ws2_32.lib`.
- Everything loaded into the game must be 32-bit (x86) with the static CRT.
